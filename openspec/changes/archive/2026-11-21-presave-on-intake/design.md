## Context

`Engine.step` 是唯一推进文件的地方：选文件、检查已有副本、本地空间预检、空间计划、转存（`Restore.ensure` 发出转存并轮询任务直到副本可用），然后下载。同时下载数大于 1 时下载交给下载池，但转存仍在串行步骤里，每次只为下一个要下载的文件转存。扫描已经由会话中独立的扫描循环进行（scan-shares-on-intake）。

自动回收 `SpaceManager.ensure` 只把所有引用文件都已交付的副本当作候选（`Store.candidates` 与 `canReclaim`），下载中或尚未下载的副本不会被删除。

## Goals / Non-Goals

**Goals:**
- 文件入队后尽快转存到云盘，下载不必等转存。
- 云盘放不下时先回收已交付的副本，仍放不下时等待，不打乱下载顺序。
- 暂停、取消与停止对预先转存同样及时生效。

**Non-Goals:**
- 不并发转存：一次只有一个转存在进行，与原来相同。
- 不为预先转存删除未交付的副本，也不改变回收候选的规则。
- 不改变任务库结构或文件状态机：已转存、等待下载的文件沿用 `awaiting_remote`，由界面结合副本状态区分显示。
- 预先转存不做本地空间预检：本地空间只在开始下载前检查，与云端转存无关。

## Decisions

### 1. 独立的预先转存循环

会话在启动核对（`Engine.reconcile`）之后启动预先转存循环，与扫描循环、执行器循环并行；有进展就继续，否则空闲等待（与扫描循环相同的 500 毫秒或被唤醒）。每次调用 `Engine.presave`：

- 门槛与串行步骤相同：任务库被阻止、用户暂停队列、任何系统暂停或账号限流时不进行。
- `Store.nextPresave` 按 `rowid`（队列顺序）选第一个没有保留副本、也没有已发出转存的文件；状态限于排队、等待空间与到期的稍后重试；排除取消与暂停的文件和分享、下载池中的文件、手动释放中的文件以及串行步骤当前的文件。选择与登记（`presaveTarget`）之间没有 `await`。
- 取得转存锁后复查文件仍需转存，先核对来源（`Restore.checkSource`），再在云端操作锁内做空间计划（`SpaceManager.ensure`），然后改为 `ready` 并转存（`Restore.ensure`），文件停在 `awaiting_remote`、副本已记录。
- 空间计划结果为放不下（`waiting_space` 或 `waiting_sync`）时停在这个文件：不改变状态，到 `presaveWaitUntil`（60 秒后）之前不再尝试；`completed` 与 `copy_released` 事件清除这个时间，立即重新评估。不跳过它转存后面的文件，避免较小的后续文件占满空间、让大文件迟迟等不到。
- 单文件超过云盘总容量时与串行步骤相同，记为失败。
- 错误按串行步骤的同一分类处理（`Engine.failed`）。

### 2. 转存锁

预先转存与串行步骤的转存（核对来源、空间计划、发出转存直到副本可用）都在 `Engine.saving` 中执行，按请求顺序一次一个。否则两个转存可能同时通过空间计划，在任一副本计入容量之前都认为空间足够。等锁期间信号中断时立即放弃，不等前一个转存结束，也不打乱后面的顺序。锁的顺序是转存锁在外、云端操作锁在内；手动释放只取云端操作锁，不会互相等待。

### 3. 下载顺序

串行步骤用 `nextFile` 选下一个文件，不排除预先转存中的文件。选中的文件正在预先转存时，步骤等这次预先转存结束（或步骤被中断）后返回，下一步重新选择：通常这时文件已有副本，直接下载；放不下时由步骤按原有流程记为等待空间。这样下载顺序与队列一致。预先转存则排除串行步骤当前的文件。

### 4. 中断

- `stopActive` 同时中断匹配的预先转存并等它返回：取消、暂停文件或分享、暂停队列、登出与停止会话都经过它。
- 账号级暂停（`pause` → `haltPool`）与限流同样中断预先转存。
- 发出转存前被中断：转存意图记为未提交，文件保持原状态，不记为失败。发出后被中断：转存操作已记录任务 ID，下一次（串行步骤、预先转存或启动核对）继续核对，不重复转存。
- 手动释放不处理预先转存中的文件。

### 5. 界面

- `awaiting_remote` 且最近一份副本为保留中的文件显示“已转存，等待下载”（`·`，云端色调），不显示动态图标；用户暂停队列时不显示为已暂停（它并不在执行中）。分享行把它们计为“已转存”，与“转存中”分开。
- 预先转存开始时发出 `presaving` 事件，事件区与下载前转存一样显示“正在转存”；转存完成发出 `presaved` 事件，不写入事件区，界面据此刷新云盘容量。

## Risks / Trade-offs

- [云盘更快被占满，自动回收更早删除已交付的副本] → 与用户要求一致：放不下时先回收再转存。只删除已交付的副本，规则不变。
- [请求更多：下载期间同时有转存请求] → 转存仍然串行；限流时预先转存与下载一起等待。
- [放不下时每 60 秒重新核对来源与容量] → 只有排在最前面的一个文件，请求量很小；有文件交付时立即重新评估。
- [取消一个已预先转存、尚未下载的文件后副本留在云盘] → 与取消下载中的文件相同：副本保留，可以手动释放；任务完成或取消后按现有规则成为可释放的副本。
