## Context

- 手动释放（`Engine.release`）以 `Store.releaseTargets` 选出目标：保留中的本工具副本，加上云端已没有副本、可以直接删除记录的文件（`forgettable`）。`forgettable` 只接受 `state='completed'`，所以已取消的文件既不能删除记录，释放副本后记录也不会删除；分享记录只有在扫描完整完成后才能删除，扫描失败后取消的分享永远留在列表中。
- `IntakeReceiver.receive` 的去重游标 `acceptedSequence` 初始为 `null`，启动后第一次读取总会被当作新的复制事件。
- 事件区高度固定为 `EVENT_LINES = 3`，`LiveController` 最多保留 50 条事件。
- 剪贴板接收已经发出 `received` 事件并写入事件区，但终端在后台时用户看不到。

## Goals / Non-Goals

**Goals:** 已取消的任务能从列表中彻底删除；剪贴板接收有明确、即时的反馈；可以回看更多事件；启动时不再接收旧的剪贴板内容。

**Non-Goals:** 不删除已交付的本地文件；不为窗口前置提供开关；`watch` 不前置窗口；事件区不提供逐行滚动。

## Decisions

1. **“可删除记录”扩展到已取消的文件。** `forgettable` 改为：已完成，或者文件本身或所属分享已取消；其余条件不变（没有未删除的副本引用、没有未确认操作、没有单项系统暂停）。`ReleaseTarget.completed` 改名为 `finished`，含义为“引用该副本的文件都已完成或已取消”。因此：
   - 对已取消文件按 `x`：有保留中的本工具副本时，确认后释放副本，再删除记录；没有副本时打开“删除任务记录”确认框。
   - `X` 全部释放的候选从“已完成”扩大为“已完成或已取消”。仍在进行中的任务不受影响。
   - 非本工具创建的副本仍会阻止删除（与已完成文件一致），界面说明原因。
2. **已取消且没有文件的分享也可以删除。** `shareForgettable` 改为：没有文件记录、没有进行中的扫描，并且分享已取消，或扫描已完整完成且没有待执行的重新扫描。`releaseTargets` 额外返回范围内这样的已取消空分享；预览的 `removed` 把每个空分享计为一条记录，确认框对没有文件的分享使用“删除分享的任务记录”。
3. **删除已取消文件的记录前，先删除它的临时文件。** 临时文件 `<名称>.pikpak-part` 是本工具独占的未完成数据；只删记录而留下它，之后重新下载同一分享时会因同名临时文件已存在（以 `O_EXCL` 创建）而失败。`FileWorkspace.discardTemporary` 按目录句柄打开临时文件、核对任务库记录的身份，关闭后按核对过的目录路径删除；文件不存在视为已删除。核对失败或删除失败时保留任务记录，事件区说明原因。平台文件层没有句柄相对的删除操作，核对与删除之间有极短的竞争窗口；目标只是记录在案的 `.pikpak-part` 文件，接受这一风险，不为三个平台各加一个删除原语。
4. **启动监听后的第一次读取作为基线。** `RuntimeSession.startIntake` 每次启动监听（程序启动或设置中重新开启）都标记“下一次快照为基线”；读到第一份稳定快照时调用 `IntakeReceiver.baseline(snapshot)`，只记录序号，不解析、不接收。之后序号变化（新的复制事件，即使文本相同）照常接收。监听关闭期间复制的文本也不会在重新开启时被接收，用户可以用 `a` 粘贴。
5. **接收来源写入事件。** 剪贴板接收产生的 `received`、`received_cancelled`、`intake_issues` 事件带 `reason: "clipboard"`；手动粘贴与补填提取码不带。事件区据此写“已从剪贴板接收分享…”。
6. **窗口前置只在全屏界面、只在剪贴板事件时触发，尽力而为。** `LiveController` 收到 `reason: "clipboard"` 的接收事件时调用注入的 `activate`，1 秒内最多一次。`src/platform/window.ts` 按平台实现，任何失败都静默忽略：
   - Windows：经 `bun:ffi` 取 `GetConsoleWindow`，再取 `GetAncestor(GA_ROOTOWNER)` 得到真正的顶层窗口（Windows Terminal 的伪控制台窗口归属于终端窗口；传统控制台窗口就是它自己）。有些宿主（编辑器或桌面应用的内置终端）的伪控制台窗口不可见、也没有归属窗口，激活它只会让用户当前的窗口失去焦点，所以窗口不可见时跳过。最小化时先 `ShowWindow(SW_RESTORE)`，再临时 `AttachThreadInput` 到当前前台线程，调用 `BringWindowToTop` 与 `SetForegroundWindow`，以绕过前台锁。
   - macOS：终端应用会把自己的包标识写入子进程环境变量 `__CFBundleIdentifier`，用 `open -b <标识>` 激活该应用，不需要自动化权限。
   - Linux：X11 下存在 `WINDOWID` 且安装了 `xdotool` 时执行 `xdotool windowactivate`；Wayland 没有通用办法，只依赖事件区。
7. **事件区展开与折叠。** 主面板按 `l` 切换，状态只在本次界面中保存。折叠时显示最近 3 条；展开时显示最近 `max(3, ⌊行数 / 2⌋)` 条（不超过已有条数），列表高度相应减少。按键提示行在中文“继续/全部开始”状态下已接近 100 列，放不下新按键，所以提示放在事件区上方分隔线的右侧，并写明按下后的操作（“l 展开日志”/“l 收起日志”）。
