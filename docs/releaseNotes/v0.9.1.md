# PikPak DL CLI v0.9.1

发布日期：2026-10-21

界面支持简体中文、英文和日文，并能识别 PikPak 各语言版本复制的分享文本。

## 新功能

- **界面语言**：全屏界面、命令行帮助与输出、`watch` 的提示、错误信息和浏览器里的授权页都支持简体中文、English 和日本語。
  - 默认跟随系统语言：中文系统（包括繁体中文）显示简体中文，日文系统显示日文，其他语言显示英文。
  - 设置页新增“语言”项，用 ←→ 切换，界面立即改用新语言。
  - 命令行使用 `config --language <auto|zh-CN|en|ja>`，`auto` 恢复跟随系统。
  - 分享标题与文件名保持原样；`status` 输出的 JSON 字段与原因代码不随语言变化，脚本可以照常使用。
- **英文与日文文档**：新增 `README.en.md`、`README.ja.md`，以及 `docs/en/`、`docs/ja/` 下的使用说明。

## 改进

- **识别更多语言的分享文本**：PikPak 网页版与 Android 应用在各种界面语言下复制的分享文本都能识别提取码，包括繁体中文、英文、日文、韩文、印尼文、马来文、西班牙文、葡萄牙文、俄文和阿拉伯文。
- **识别常见的提取码写法**：
  - 同义标注：识别码、访问码、提取密码、分享码、口令、パスコード、access code 等。
  - 全角冒号或等号，“是/为/は/is”。
  - 括号或引号包住的码，如 `【提取码：abcd】`；码紧跟在标注后，如 `提取码abcd`。
  - 冒号在行尾、码写在下一行。
  - 全角字母与数字。
- **英文和日文界面的排版**：标签列按当前语言的文字加宽，按键提示在 100 列宽的窗口中完整显示；状态说明较长时只截断状态列，文件名不再被挤成两行。

## 修复

- **不再把其他密码当成提取码**：分享说明中的解压密码、账号或登录密码、Vault 密钥和 Wi-Fi 密码会被忽略。此前同时附带解压密码的分享文本会被判为“配对不明确”而无法接收。
- **带括号的链接**：`链接（提取码：…）` 这类写法中，链接不再吞掉后面的括号内容。

## 升级说明

直接替换可执行文件即可。任务库结构不变，语言设置保存在已有的配置中，不需要迁移或重新登录。

升级后界面会按系统语言显示：系统语言不是中文或日文时，原来的中文界面会变成英文。想继续使用中文，在设置页把“语言”改为简体中文，或运行 `config --language zh-CN`。

英文等以空格分词的语言中，提取码标注与码之间需要冒号、等号或 `is`（如 `Password: abcd`）。PikPak 生成的分享文本都带冒号，不受影响。

## 已知问题与待验收

- PikPak 网页版的日文界面复制的分享文本里没有提取码（“パスワード:”后面是空的，是网页版模板的问题）。这时分享按无提取码接收，并提示需要提取码；补上提取码后重新复制或粘贴即可。
- Vault 加密分享（使用解密密钥）与 PikPak 的“分享代码”（链接的别名）不受支持。
- Windows 上的系统语言检测（读取系统显示语言）尚未实机验证；Linux 已用编译产物验证。
- 日文界面与日文文档尚未经母语使用者审阅，欢迎反馈不自然的用语。
- v0.8.1 列出的待验收项仍然有效：macOS、Windows arm64、Windows 传统控制台、Linux 桌面与 Linux arm64 尚未在实机上完整演练。
