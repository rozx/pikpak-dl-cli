# PikPak DL CLI v0.10.2

发布日期：2026-11-21

修复浏览器授权无法完成的问题：PikPak 授权页改版后不再列出任何权限，“授权”按钮无法点击。复制分享后，文件不再等轮到下载才转存，而是先依次转存到云盘，下载按顺序跟上。

## 改进

- **复制后先转存到云盘**：以前每个文件要等轮到下载时才转存，下载期间云端什么也不做，下一个文件开始前还要先等它转存完成。现在分享扫描后，程序按队列顺序把文件逐个转存到云盘，下载按顺序跟上，轮到已转存的文件时直接下载。云盘放不下下一个文件时，先回收已下载完成的副本（最旧的先回收）；仍放不下就停在这个文件，等有文件下载完成后再转存，不会跳过它先转存后面的文件。已转存、等待下载的文件显示为“已转存，等待下载”，分享行单独统计已转存的数量，标题区的云盘容量随转存更新。暂停队列或登录失效等系统暂停期间不转存；取消或暂停正在转存的文件会立即中断这次转存，文件不记为失败。

## 修复

- **授权页没有权限、无法授权**：PikPak 授权页现在只显示应用在授权请求中列出的权限。以前的版本只请求登录基础范围，授权页的权限列表是空的，“授权”按钮呈灰色，首次登录、`login --force` 与账号页的重新授权都无法完成。现在程序在授权请求中列出全部四项应用权限（账号信息、管理文件、分享、云下载），授权页逐项显示“管理文件”“云下载”“账号设置”，保持全部勾选即可授权。
- **不再要求分享权限**：改版后的授权页不向本工具提供“分享”这一项，授权结果中没有它，以前的判定会认为缺少必需权限而不保存授权。没有分享权限也能正常扫描、转存与下载分享，所以分享改为建议权限。现在必须授予的只有账号信息与管理文件；本地登录页、全屏界面的重新授权提示和 `permissions` 命令都按此显示。

## 升级说明

直接替换可执行文件即可。任务库结构不变，不需要迁移。已登录且会话有效时不需要重新登录；之前因授权页无法授权而没有登录成功的，替换后重新启动或运行 `pikpak-dl-cli login` 即可。之前已注册的本机 OAuth 客户端继续使用。

升级后启动时，已扫描但还没转存的文件会开始转存到云盘（队列暂停时除外），云盘会比以前更早被占满，已下载完成的副本也会更早被自动回收。

## 已知问题与待验收

- 新的授权流程已在 Windows 上用真实 PikPak 账号验证：授权页列出权限并可授权，登录后扫描、转存与下载分享正常。macOS 与 Linux 由 CI 的自动测试覆盖，尚未实机登录。
- 如果 PikPak 以后要求分享权限才能读取或转存分享，相关操作会被拒绝并以权限原因暂停，界面会显示原因。
- 复制后先转存已由自动测试覆盖（按顺序转存、空间不足时先回收再转存、仍放不下时等待、暂停与取消中断转存、下载顺序不变），尚未用真实 PikPak 账号在全屏界面中实机验证。
- 下载期间同时有转存请求，账号限流可能比以前更早出现；限流期间转存与下载都按服务端要求等待。
- v0.10.1、v0.10.0、v0.9.2、v0.9.1 与 v0.8.1 列出的待验收项仍然有效。
