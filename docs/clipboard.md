# 复制分享文本

复制一次完整文本，让链接与提取码同时出现在同一快照中。以下仅为合成格式示例，没有真实资源：

```text
链接：https://mypikpak.com/s/synthetic-one
密码：demo
```

提取码可以用 PikPak 各语言客户端复制时的标注，也可以用常见同义词：

- 中文：提取码、提取密码、密码、识别码、访问码、分享码、口令等，简繁体都可以。
- 其他语言：Password、Pass code、Access code、パスワード、パスコード、비밀번호、Kata sandi、Kata laluan、Contraseña、Senha、Пароль、كلمة المرور 等。

标注后可以跟冒号（含全角）、等号、空格或“是/为”，码也可以放在括号或引号里；冒号在行尾时，码可以单独写在下一行，但这一行须是最后一行或后面空一行（否则可能是模板里的文件名，不会当成提取码）。英文等以空格分词的语言，标注与码之间需要冒号、等号或 `is`。解压密码、账号或登录密码、Vault 加密分享的密钥和 Wi-Fi 密码不会被当成提取码。标注后同一行没有内容时按未提供提取码处理；PikPak 网页版的日文界面复制的文本就是这样（“パスワード:”后面是空的），需要补上提取码后重新复制或粘贴。

没有任何标注时，只有一种写法会被识别：整段文本只有一行链接和一行单独的提取码（中间可以有空行）。其他没有标注的文字一律不当成提取码。

也支持链接内明确标记的 `pwd`、`password`、`passcode` 或 `pass_code` 参数；无码分享可以只复制链接。真实缺码、错误码分别已观察到 `PASS_CODE_EMPTY`、`PASS_CODE_ERROR`，不会被当成全局账号失效。这时分享行会以红色显示“分享需要提取码”或“提取码错误”：选中该分享按 Enter 输入提取码即可重新扫描，也可以重新复制完整文本。之后单独复制的提取码不会自动配对到等待中的分享。

多个分享可以分别占一行或一段，且每个码明确配对。一个码跟在多条无法区分的链接之后时不会猜测；请分别复制。相似域名、其他 PikPak 页面、单独的提取码和普通文本不会创建任务。原始剪贴板不写入日志或数据库。

看到任务 ID 的接收确认才表示资料与请求已保存。一次复制中部分分享保存失败时，已确认的分享保留，监听仅重试未确认部分。剪贴板是当前内容快照：快速复制可能覆盖尚未读取的内容，变化计数不能还原历史；未看到确认时请重新复制。

再次复制相同文本可以触发增量扫描；保持剪贴板不变不会不断扫描，也不会定时监视远端分享更新。完成且未变化的版本即使本地成果已移走，也不会自动重下；同名新版本保留旧成果。失败预算耗尽后，停止监听并用 `retry <任务ID>` 开启新的有限尝试周期；复制分享不会重置文件重试预算。

更改默认目录时，新分享和本地还没有任何内容的分享改用新目录；已开始下载或已完成的分享的后续文件继续使用原目录。`cancel` 保留资源和取消标记；重新复制同一分享也不会重新启动被取消的分享。在界面中按 `x` 可以删除已取消的任务，见[云端空间](cloud-space.md)。

全屏界面默认开启剪贴板监听，可在设置页关闭，关闭后按 `a` 粘贴分享文本；粘贴框与剪贴板使用同一解析规则。剪贴板读取隔离在子进程，故障不会阻塞下载。macOS 读取系统剪贴板快照，Windows 通过系统 PowerShell 读取，Linux 调用 `wl-paste`（Wayland）或 `xclip`、`xsel`（X11）；没有可用的剪贴板时界面显示监听异常，粘贴仍然可用。

每次开始监听（程序启动，或在设置页重新开启监听）时，剪贴板里已有的文本只记作起点，不会被接收；之后的复制才会接收，复制相同的文本也算。需要接收启动前复制的内容时，重新复制一次或按 `a` 粘贴。

全屏界面从剪贴板接收到分享时，事件区写明“已从剪贴板接收”，并尝试把终端窗口带到前台：Windows 上激活 Windows Terminal 或控制台窗口（编辑器内置终端等没有可见窗口的宿主会跳过），macOS 上激活启动程序的终端应用，Linux X11 下安装了 `xdotool` 时激活终端窗口；Wayland 下只在事件区提示。手动粘贴和 `watch` 不会切换窗口。
