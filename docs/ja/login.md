# ログインと再認可

全画面インターフェースは初回起動時にログインを案内します。Enter を押すとブラウザで認可ページが開き、完了したらダウンロード先を選びます。コマンドラインでは `pikpak-dl-cli login` を実行します。有効なセッションがある場合は、サーバー側の本人情報と容量を確認します。ない場合はローカルの入口ページを開き、PikPak の公式ページでの認可へ案内します。パスワードは公式ページでのみ入力します。認可コードはローカルのコールバックで受け取り、PKCE S256、使い捨ての state、サーバー側のアカウント本人確認を用いて検証したうえで、トークンをシステムの資格情報ストアに保存します。

ローカルのポートが使用中の場合は、以前のログイン画面に対応するこのツールのプロセスを終了してから再試行してください。ブラウザを自動で開けなかった場合は、ターミナルに表示されたローカルの入口ページを手動で開いてください。アカウントのパスワードをチャット、コマンドライン引数、設定ファイルに貼り付けないでください。公式ページで追加の確認を求められた場合は、そのページで完了してください。このプログラムは確認を回避せず、認可エラーを際限なく再試行することもありません。

PikPak の認可ページにはアプリの権限が一つずつ表示されるので、すべて選択してください。必須なのはアカウント情報（`account`）、ファイル管理（`files:manage`）、共有（`share`）です。クラウドダウンロード（`cloud_download`）は現在このツールでは使用していませんが、あわせて選択することをおすすめします。認可から戻ると、プログラムはまずサーバーが付与した認可スコープを確認します。必須の権限が不足している場合は今回の認可を保存せず、ブラウザのページに不足している権限と「再認可」ボタンを表示し、ターミナルにも同じ内容を表示して、ログインの待機を続けます。サーバーが認可スコープを返さなかった場合や、返されたスコープにアプリの権限が一つも含まれていない場合は「確認できません」と表示し、ログインは妨げません。`pikpak-dl-cli permissions` を実行すると、サーバーが返した認可スコープと判定結果を確認できます。

全画面インターフェースの設定ページの最初の項目は「アカウント」です。Enter でアカウントページに入ると、アカウント名、メールアドレスと ID、会員の状態と有効期限、クラウド容量、各権限が付与されているかどうかを確認できます。アカウントページで `r` を押すと再認可、`l` を押すとログアウト（確認あり）です。どちらも、まず現在のダウンロードを安全な位置で停止して進捗を保存します。再認可をキャンセルした場合は、Esc で元のアカウントに戻ります。起動時に保存済みの認可で必須の権限が不足していると、画面に再認可が促されます。Esc でひとまずそのまま使い続けることもできます。

`login --force` はブラウザでの認可をやり直します。現在のブラウザによる経路は事前の実地検証を済ませているため、検証していないアカウント・パスワード方式の代替経路は有効にしていません。権限の拒否や更新の失敗が起きた場合は、まず `watch` を停止してからログインし直してください。本人情報と容量の読み取りに成功しても、現在のアカウントに完全削除の権限があるとは限りません。個々の操作が拒否された場合は、引き続き実行を一時停止します。

`logout` は認証トークンを削除し、アカウントのタスク、共有情報、ローカルのダウンロード結果は保持します。同じアカウントで再度ログインすれば再開できます。別のアカウントでログインしても、以前のアカウントのリソースを実行したり削除したりすることはできません。

Windows での対応するコマンド：

```powershell
.\pikpak-dl-cli-windows-x64.exe login
.\pikpak-dl-cli-windows-x64.exe watch --output "$env:USERPROFILE\Downloads"
.\pikpak-dl-cli-windows-x64.exe status
```

Windows arm64 では、同じフォルダの `pikpak-dl-cli-windows-arm64.exe` を使います。監視を停止したあとは、`retry`、`cancel`、`config`、`logout` を同じ意味で使えます。

macOS では、このアプリ用のキーチェーン項目を使います。Linux では libsecret を介して Secret Service（GNOME Keyring、KWallet など）の同名の項目を使い、キーリングのロックを解除しておく必要があります。利用できるサービスがない場合（グラフィカルセッションのないサーバーなど）は、資格情報ストアを利用できないと報告し、平文には切り替えません。Windows ではブリッジがシステムの PowerShell から資格情報マネージャーの `CredWriteW` を呼び出し、`CRED_PERSIST_LOCAL_MACHINE` を明示的に指定したうえで、永続化フラグと値を読み戻して確認します。秘密情報はプロセス間のパイプだけを通り、コマンドラインや通常のファイルには入りません。2560 UTF-8 バイトを超える場合は保存を拒否し、平文には切り替えません。フィールドと制限は [Microsoft CREDENTIALW のドキュメント](https://learn.microsoft.com/en-us/windows/win32/api/wincred/ns-wincred-credentialw) に基づいています。

システムの資格情報ストアが利用できない、ロックされている、ポリシーでブリッジが禁止されている、データが長すぎる、といった場合は、その問題を解決してから再試行してください。タスクのアクセス情報の参照を読み取れない場合は、リンクとパスコードを含むテキスト全体をもう一度コピーする必要があります。これを共有の恒久的な失効と誤判定することはなく、別のタスクの情報を自動で流用することもありません。情報を更新すると新しい参照を使い、古い参照は進行中のスキャンと結果不明の操作が使い終えてから回収されます。
