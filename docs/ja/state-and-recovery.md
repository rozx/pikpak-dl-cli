# ローカルの状態と復旧

既定の状態ディレクトリは、macOS では `~/Library/Application Support/PikpakDownloader`、Windows では `%LOCALAPPDATA%\PikpakDownloader`、Linux では `$XDG_DATA_HOME/PikpakDownloader`（未設定の場合は `~/.local/share/PikpakDownloader`）です。`PIKPAK_DOWNLOADER_STATE_DIR` を使うと、ローカルでのテスト用に別のディレクトリを指定できます。同じタスクデータベースのパスに書き込むインスタンスは常に一つでなければなりません。認証の資格情報は現在のシステムユーザーのこのアプリに属するため、初版では異なる状態ディレクトリで複数の実行プロセスを同時に動かさないでください。ダウンロードしたファイルは、共有を受け付けた時点で固定された出力フォルダに置かれ、タスクデータベースがダウンロード先と一緒に移動することはありません。

`tasks.sqlite` には、アカウント ID、情報の参照、固定された出力ルート、スキャン世代、ファイルのバージョン、保存・削除・書き込みの意図、引き渡しの記録を保存します。パスワード、トークン、パスコード、クリップボードの元の内容、署名付き URL はタスクデータベースに入りません。資格情報はシステムの保護されたストレージが保持します。データベースのバックアップだけでは、資格情報のバックアップや再認可の代わりにはなりません。

スキーマのバージョンには SQLite の `user_version` を使い、別途アプリの識別子も検証します。プログラムは、より新しいスキーマや別のアプリのデータベースへの書き込みを拒否します。現在のバージョンは 5 で、スキャンの進捗、フォルダの ID、書き込み先パスの対応付け、分割ダウンロードのチェックポイント、一時停止の印を含みます。開発期のバージョン 1–4 からの移行に対応しています。移行は書き込みロックを保持し実行を止めた状態で、まず復旧確認の印付きの一貫性のあるバックアップを作成し、そのうえでトランザクション内でアップグレードします。自動でのダウングレードは行いません。

バックアップ機能は、`backup_review_required` の印が付いた非公開の一貫性のあるスナップショットを作成し、既存のファイルは上書きしません。古いスキーマのスナップショットは読み取り専用の SQLite ツールで調べられますが、そのまま実行中のキューとして使うことはできません。現在の CLI の状態照会は現在のスキーマを使います。古いバックアップには、その後に行われた保存、書き込み、完全削除が抜けている可能性があります。復旧の際は、まず結果不明のリモート操作、ローカルファイルの ID、すでに行われた引き渡しを確認し、管理された復旧手順で書き込みを有効にする必要があります。初版には、古いバックアップを自動で復元してすぐに続行するコマンドはありません。

タスクデータベースを失った場合、クラウドにある同名のファイル、同じ内容、既存のフォルダが自動でこのツールの所有になることはありません。再インストールしても、名前を頼りにそれらを引き継いだり削除したりはしません。ローカルの過去の完了記録も、フォルダをスキャンするだけでは再構築できません。このツールはバックアップ修復やフォルダ同期のためのツールではありません。

SQLite は WAL、`synchronous=FULL`、外部キー、短い同期トランザクションを使います。ネットワークや資格情報の操作をトランザクションのコールバックに入れることはできません。データのサイズは十進数の文字列として保存して `bigint` に変換し、リクエストのバージョンと再試行回数には正確な整数を使います。

実行の排他制御には別ファイルの `queue-lock.sqlite` を使います。インスタンスはその EXCLUSIVE トランザクションが使うシステムのファイルロックを保持し、終了やクラッシュの後はシステムがロックを解放します。ファイルが存在するかどうかで使用中かを判断することはなく、タスクデータベースで長いトランザクションを保持することもないため、実行中のキューも `status` で読み取り専用で照会できます。プロセスをまたいだ占有、変更の競合、強制終了後のロックの再取得は、macOS、Windows、Linux 上のテストで確認しています。
