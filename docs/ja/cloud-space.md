# クラウドの容量と回収

クラウドドライブは中継にだけ使います。完了したコピーの完全削除を検討するのは、次のファイルが収まらないときだけです。クラウドの容量が足りている間は、前もって空にすることはありません。まずローカルの保存先と、確認できる残りのダウンロードバイト数を調べ、次に共有と元のバージョンを検証してから、クラウドの容量計画を立てます。

回収の候補は、次の条件をすべて満たす必要があります。現在のアカウントのものであること、このツールが保存した明確な作成の証拠があること、ローカルでの内容の検証と書き込みが完了していること、すべての参照が引き渡し済みであること、現在のリモートの ID、バージョン、名前、親フォルダが記録と一致していること。証拠には、今回のリクエストで返された個別の保存タスク、正確な取得元の対応付け、元の共有と元ファイルの識別子、新規作成の時系列、内容のフィンガープリントが含まれます。名前、時刻、サイズのいずれか一つだけでは、所有を認めるには足りません。

最後の参照がローカルで完了した時刻の古い順に処理し、時刻が同じ場合はリモート ID の順にします。まず有効な候補の合計で足りることを確かめ、それから一件ずつ改めて確認し、削除の意図を記録して、正確な ID だけを送信します。削除のたびに結果と実際の容量を確認し、次のファイルに必要な空きが確保できた時点で止めます。ゴミ箱全体を空にしたり、フォルダを再帰的に削除したりすることはありません。

完了したローカルの結果はユーザーが管理します。あとでローカルファイルを移動、変更、削除しても、クラウドのコピーがこれまでに得た回収の資格は取り消されません。未完了、失敗、キャンセルされてまだ引き渡されていない、所有が不明、名前の変更・移動・内容の変更を受けた、未完了の参照がまだある、といったコピーは自動回収の対象になりません。

初めて使うときにクラウドドライブがすでにいっぱいの場合や、失敗したコピーしかなく安全に回収できる対象がない場合は、空きができるのを待ちます。ほかの小さなファイルは続けて処理できます。一つのファイルがアカウントの総容量を超える場合は、はっきりと失敗させ、そのために無駄な削除はしません。

削除の応答が失われた場合は、同じ対象を確認し、ほかのリソースを代わりに削除することはありません。自動回収で権限が拒否された場合は実行を一時停止します。容量がなかなか更新されない場合は、一定時間待ってから同期待ちと表示し、リクエストの成功をすぐに全容量が解放されたものとは見なしません。転送量の上限、レート制限、認証の失敗、ローカルディスクの問題では、クラウドの回収は始まりません。

## 手動での解放

画面でファイルや共有を選んで `x` を押すと、次のファイルが容量を必要とするのを待たずに、そのクラウドのコピーをすぐに解放できます。`X` を押すと完了・キャンセル済みのすべてのタスクのクラウドのコピーを解放し、進行中のタスクには影響しません。解放中のファイルには「解放中」と表示されます。対象となる条件のうち自動回収と共通するのは、このツールが作成し、所有の証拠があり、まだ保持中のコピーだけを扱うこと、そして削除の前にリモートの ID、名前、親フォルダ、内容のフィンガープリントを改めて確認することです。異なるのは、ファイルが未完了（待機中、一時停止、キャンセル、失敗、待ち）でもよい点です。ダウンロード中または検証中のファイル、ディスクに書き込み中のファイル、確認の済んでいない保存があるファイル、このツールが作成したものではないコピーは解放せず、画面にその理由だけを表示します。

確認画面には、削除が完全削除であること（ゴミ箱には入りません）と、ローカルファイルが残ることが表示されます。完了したファイルのコピーの解放に成功すると、そのタスク記録も削除され、一覧から消えます。クラウドにもうコピーのない完了済みタスク（以前に自動回収された場合など）も、`x` で記録だけを削除できます。共有のファイルの記録がすべて削除されると、共有の記録とパスコードもあわせて削除されます。その後に同じ共有をコピーすると、新しいタスクとしてダウンロードします。未完了のファイルは、コピーを解放すると待機中に戻り、進捗はそのまま残ります。再開すると通常の流れで共有から保存し直し、続きからダウンロードします。共有の期限が切れている場合は完了できないため、新しい共有の情報が必要です。

キャンセル済みのタスクは完了済みと同じように扱います。コピーを解放すると記録を削除し、クラウドにコピーがない場合は記録だけを削除できます。キャンセル済みのファイルの記録を削除する前に、未完了の一時ファイル（`.pikpak-part`）を記録された ID と照合して削除します。すでにない場合は削除済みとみなし、ID が一致しない場合やディスクが使えない場合は記録を残して、イベント欄に理由を表示します。スキャンに失敗した後にキャンセルした、ファイルのない共有も `x` で削除できます。

手動での解放と自動回収は同じクラウド操作のロックを共有しているため、同じコピーに対して同時に削除を送ることはありません。複数のコピーをまとめて解放するときは、まず並行して確認し（同時に最大 4 リクエスト）、次に 1 バッチ最大 100 個の ID ごとに削除リクエストを一回送ります。削除が受け付けられたら、コピーが見えなくなったことをもって確認とし、クラウドの容量の更新は待ちません。まだ見えているコピーは最大 30 秒まで再確認します。削除リクエストはサイレントモードで送ります。サーバーが明確に拒否した場合（401 以外の 4xx、たとえば認可に完全削除の権限がない場合）は、コピーを保持中に戻し、削除の意図を拒否済みとして記録し、イベント欄に理由を表示します。これによってアカウントが一時停止することはありません。ログインの期限切れやネットワークの切断など、それ以外の結果は上記の規則に従い、次回の起動時に確認します。解放に成功すると、イベント欄に解放した容量を表示し、クラウドの容量を更新します。

バッチのループと上記の障害経路は、合成サービスを使ったテストで確認しています。手動での解放とすべての解放は、Windows 上で実際のアカウントを使って検証済みで、サーバーは完全削除を許可しました。
